# 第二大腦設定指南

把一個 Obsidian vault 整理成適合 AI agent 長期協作的「第二大腦」，一份**不綁定特定 agent** 的操作指南。

主要交付物只有一份文件：**[第二大腦設定指南.md](第二大腦設定指南.md)**

## 這份指南解決什麼問題

網路上談 Obsidian 第二大腦的文章不少，但多半有兩個問題：綁死某一家 AI 工具，或是只給概念不給可執行的步驟。這份指南反過來做：

- **任何 agent 都能照做。** Claude Code、Codex、opencode、Antigravity，或其他能讀寫本機檔案的 agent 都適用。工具差異一律用 `<AGENT_HOME>`／`<AGENT_RULES_FILE>` 兩個佔位符＋對照表處理，不寫死某一家的路徑。
- **可以直接執行。** 資料夾結構、規則檔、模板、剪藏流程、每週重整 prompt 全部附完整內容，不需要跳去別的文件補齊。
- **補缺，不覆蓋。** 預設不動既有筆記，成熟的 vault 也能安全套用。

品質標準是：拿給沒有背景知識的人，他能照著做完。

## 怎麼用

1. 確認你的 Obsidian vault 路徑（指南裡寫成 `<VAULT_PATH>`）。
2. 在 vault 目錄開你的 AI agent，把 [第二大腦設定指南.md](第二大腦設定指南.md) 交給它，說「照這份指南設定我的第二大腦」。
3. 也可以自己照著做——每個階段都是人看得懂的步驟，不需要 agent 也能完成。

不想整套照做的話，跳著看也行。階段〇（確認規則檔位置）和階段二（資料夾結構）是地基，其餘可依需求取用。

## 指南涵蓋的內容

| 階段 | 做什麼 |
|------|--------|
| 〇 | 確認你的 agent 讀哪一個規則檔（**最容易做錯、且錯了不會報錯**的一步） |
| 一 | 詢問使用者偏好 |
| 二 | 建立五個帶數字前綴的資料夾：輸入 → 消化 → 輸出 |
| 三 | 建立全域規則檔、vault 根規則檔，以及跨 agent 共用需要的橋接檔 |
| 四 | 建立三個純 Markdown 模板（不依賴 Templater） |
| 五 | 建立知識庫索引與操作紀錄 |
| 六 | 設定 Web Clipper 或手動剪藏流程 |
| 七 | 每週知識重整 SOP，含可直接貼給任何 agent 的 prompt |
| 八 | 歡迎筆記與驗證清單 |

文末另有**踩坑筆記**，記錄實際導入時撞到的問題——多數是「不會報錯、只會安靜失效」的那一類，例如規則檔放錯檔名、橋接檔漏建導致某個 agent 完全不套用規則。

## 支援的 agent

| Agent | 全域設定資料夾 | 規則檔名 |
|-------|----------------|----------|
| Claude Code | `~/.claude/` | `CLAUDE.md` |
| Codex | `~/.codex/` | `AGENTS.md` |
| opencode | `~/.config/opencode/` | `AGENTS.md` |
| Antigravity 2.0 | `~/.gemini/` | `GEMINI.md`（同時也讀 `AGENTS.md`） |

四家的欄位都查證自官方文件與 changelog。用其他工具的話，查該工具文件即可——指南全篇用佔位符，換一組值就能跑。

## 這個 repo 有什麼

```text
second-brain/
├── README.md              # 本檔
├── 第二大腦設定指南.md    # 唯一交付物
├── agents.md              # 專案藍圖（維護這份指南時給 agent 讀的）
└── CLAUDE.md              # 橋接檔，內容只有 @agents.md
```

`agents.md` 與 `CLAUDE.md` 是維護這個 repo 用的，不是指南的一部分——**要照著設定第二大腦的人，只需要看 `第二大腦設定指南.md`**。

發現指南有錯、路徑失效或步驟卡住，歡迎開 issue。
